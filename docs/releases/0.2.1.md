# APFS for Windows 0.2.1

Public beta. Windows Test Mode is no longer needed. APFS for Windows now uses
the official, Microsoft-signed WinFsp driver, so Secure Boot can stay on.

## Included

- Signed `APFS-for-Windows-0.2.1-Setup.exe`. It installs the official WinFsp
  2.2 if it is missing, then installs APFS for Windows.
- Signed `APFS-for-Windows-0.2.1.msi` for enterprise deployment. Install the
  official WinFsp MSI first, then this MSI, both silently.
- `SHA256SUMS.txt` with SHA-256 values for both installers.
- Service, worker, tray manager, probe, MSI, and `Setup.exe` Authenticode-signed
  by `CN=Randy Northrup` through Azure Artifact Signing, with timestamps.

## Changes

- **Official signed WinFsp, no Test Mode.** The dedicated test-signed WinFsp
  build (`WinFsp+apfs-main`) is gone. The product now depends on the official
  WinFsp 2.2.26323 release, installed system-wide. Its kernel driver is signed
  by Microsoft Windows Hardware Compatibility Publisher, and its installer and
  DLL by NAVIMATICS LLC. The pinned installer is
  `winfsp-2.2.26323.msi`, SHA-256
  `36CE01F9EEDBBE6842B7FB4BEDC79D7D4F71983E8ACEB6877B46A07B331C7E19`.
- **Read-only by default for new devices.** A device the service has not seen
  before mounts read-only. Turn on **Read/write access** for that volume in the
  tray to change files. Saved choices for volumes you already use are kept.
- **Write-ordering flush barriers.** Writes are now flushed in order around
  metadata commits, so file data reaches the device before the metadata that
  points to it.
- **Legacy driver cleanup on upgrade.** Upgrading from 0.2.0 removes the old
  test-signed driver.
- **Hard-link creation removed.** The official WinFsp driver has no way to
  create hard links, so Windows apps can no longer create new hard links on
  APFS volumes. Hard links that already exist still open and work.
- The script-based install files and the release ZIP are no longer published.
  `Setup.exe` and the MSI are the only install paths.

## Upgrade from 0.2.0

1. Run `APFS-for-Windows-0.2.1-Setup.exe`. It removes the old test-signed
   driver, installs official WinFsp if needed, and upgrades APFS for Windows in
   place. Your mount settings are kept.
2. Optional: turn Test Mode off. From an elevated prompt run
   `bcdedit /set testsigning off`, then restart Windows. Skip this if another
   installed test-signed driver still needs Test Mode.
3. Optional: turn Secure Boot back on in your firmware settings. Have your
   BitLocker recovery key ready first.

If APFS drives do not appear right after the upgrade, restart Windows once so
the old driver is fully unloaded.

## Upgrade from 0.1.0

0.1.0 was installed with PowerShell scripts. Remove it with the 0.1.0
uninstall script first. Setup detects a script-based install and stops with a
message until it is removed:

```powershell
& "$env:ProgramFiles\APFS for Windows\uninstall-apfs-for-windows.ps1" -RemoveFiles
```

## Uninstall

Uninstalling APFS for Windows leaves WinFsp installed, because other apps may
use it. Remove **WinFsp** from Installed apps separately if nothing else needs
it.

## Known limits

- Write performance is still slow. Writes are committed one operation at a
  time, so copying many small files takes a long time and slows further as a
  directory grows. This stays until the new write engine, which is planned,
  replaces the current one.
- A volume is write-protected from Windows when any folder on the volume holds 1,000 or more items, or folders are nested more than 16 deep
  anywhere on it. It still lists and reads completely; changes report "The
  media is write protected". Many Mac system and user volumes exceed this;
  simple external drives usually do not. This stays until the new write
  engine.
- Creating new hard links from Windows is not supported.
- Physical surprise-unplug and power-loss recovery are untested. Synthetic
  process-termination and raw interruption tests passed.
- Application signing gives these files a verified publisher. It does not
  guarantee Smart App Control or SmartScreen reputation.
- Not production-ready.

## Requirements

- Windows 11 x64 only.
- Administrator access for installation.
- Official WinFsp 2.2 (installed by `Setup.exe` when missing).

Read the [installation guide](https://github.com/RandyNorthrup/apfs_for_windows/blob/main/docs/INSTALLATION.md)
before installing.
