# APFS for Windows 0.2.0

Public beta. Ships as a signed MSI installer. The tray manager is rebuilt, and
this release fixes security and reliability problems found in 0.1.0.

## Included

- Signed MSI installer (`APFS-for-Windows-0.2.0-test-signed.msi`) as the main
  way to install, with silent `msiexec` support for enterprise deployment.
- Service, worker, tray manager, probe, and WinFsp runtime DLL
  Authenticode-signed by `CN=Randy Northrup` through Azure Artifact Signing,
  with timestamps. The MSI is signed too. Qt and Visual C++ runtime files keep
  their original Qt Company and Microsoft signatures.
- Visual C++ runtime bundled app-local, so clean Windows installs need no
  separate redistributable.
- Rebuilt tray manager:
  - icon color shows service and mount state;
  - one submenu per volume with Open, Read/write access, Mount automatically,
    Change drive letter, and Unmount or Mount;
  - Search for APFS devices, Settings (Start at sign-in, Show notifications),
    View logs, About, Open, and Exit;
  - notifications when a volume mounts or is removed, when the service stops or
    starts, and when a drive letter is already in use.

## Security fixes

- Service IPC checks who is calling. Only elevated administrators can add a new
  mount target. Signed-in interactive users can manage volumes the service
  already knows about. Network callers are refused.
- The `ProgramData\APFS for Windows` policy and log directory is locked down so
  standard users cannot change mount policy.
- Driver registration no longer uses `regsvr32`, which overwrote the
  `WinFsp.Np` network provider and `EventLog` keys owned by a stock WinFsp
  install. The service now registers and unregisters only its own side-by-side
  driver.

## Reliability fixes

- Volumes unmount cleanly when the service stops or Windows shuts down. Workers
  get a stop event instead of being terminated.
- Workers run inside a job object, so they never outlive the service.
- Worker restarts back off instead of restarting in a tight loop.
- Configuration writes are atomic.
- An ejected (unmounted) volume stays unmounted until the device is
  disconnected and reconnected, or until you choose Mount again.
- Fixed a worker use-after-free when the same file was opened twice.
- Rename with the replace flag is handled safely. It works when the target does
  not exist, which many apps request when saving, and it still refuses to
  overwrite a different existing file.
- Paging writes (WinFsp ConstrainedIo) are clipped to the current end of file
  and never change the file size.
- Directories with more than 1000 entries list completely.
- New mounts get the lowest free drive letter, starting at `D:`.
- Tray autostart now comes from one machine Run entry; the duplicate logon
  scheduled task is gone.

## Upgrade from 0.1.0

0.1.0 was installed with PowerShell scripts. Remove it with the 0.1.0
uninstall script before you install the MSI. The MSI detects a script-based
install and stops with a message until it is removed:

```powershell
& "$env:ProgramFiles\APFS for Windows\uninstall-apfs-for-windows.ps1" -RemoveFiles
```

Leave Test Signing enabled if you plan to install 0.2.0 straight away.

## Known limits

- The filesystem driver is still WDK test-signed. Windows Test Signing (Test
  Mode) is still required, and Secure Boot must be off. Production kernel
  signing needs an EV certificate and Microsoft Partner Center attestation,
  which this project does not have yet.
- Application signing gives these files a verified publisher. It does not
  guarantee Smart App Control or SmartScreen reputation.
- Physical surprise-unplug and power-loss recovery are untested. Synthetic
  process-termination and raw interruption tests passed.
- Writes are committed one operation at a time, so creating many small files
  is slow and slows further as a directory grows (about 4 seconds per new
  file in a directory of several hundred files on a 64 MB test image). Reads,
  large files, and ordinary edits are not affected the same way.
- Reinstalling right after an uninstall needs a restart first: Windows keeps
  the file system driver loaded until then.
- Not production-ready.

## Requirements

- Windows 11 x64 only.
- Administrator access for installation.
- Windows Test Signing enabled for the included test-signed filesystem driver.
- Secure Boot disabled when required by Windows Test Signing.

Read the [installation guide](https://github.com/RandyNorthrup/apfs_for_windows/blob/main/docs/INSTALLATION.md)
before installing.
